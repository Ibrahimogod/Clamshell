# Clamshell milestone plan (Phase 3)

Each milestone ends with a **demo** you can run yourself, **tests** that run in CI (or locally for hardware-bound ones), and a **CHANGELOG entry**. No milestone starts until the one before it meets its exit criteria. If a spike fails, I stop and come back to you with options instead of working around it silently.

Estimates are focused engineering days for me plus calendar time for things only you can do (device tests, router changes, work-network runs). They are rough; M1 tightens them.

| | Milestone | Core result | Estimate | Needs you |
|---|---|---|---|---|
| M1 | LAN video | Mac screen on the Duo over Wi-Fi, 1:1, 120 Hz, measured | 8–12 d | Duo + Mac on the same Wi-Fi; 240 fps camera; run the upload test |
| M2 | Input | MacBook-exact keyboard and trackpad, fitted acceleration | 6–9 d | 2 tuning sessions (≈30 min each) |
| M3 | Internet, pairing, fallbacks | Connect from work over 443 only, < 3 s; pairing; recover < 2 s | 12–16 d | Router port forwards; one Network check run at work; one cellular run |
| M4 | Duo UX | Postures, deck modes, cover glance, hardware keyboard and mouse | 8–12 d | Posture testing on the real Duo |
| M5 | Extras | Audio, clipboard, files, multi-display, wake, auto-start | 8–12 d | — |
| M6 | Hardening | Fuzzing, security tests, optional VPS relay, HTTPS-stream path, App Store prep | 10–14 d | VPS only if you want P5 |

Total ≈ 52–75 engineering days.

## M1: LAN video (and the four day-1 probes)

**Goal:** prove the video path and kill the biggest unknowns before anything else is built on them.

**Day-1 probes (before the pipeline):**
1. **A20 HEVC 4:4:4 decode** (`VTIsHardwareDecodeSupported` + a real 4:4:4 Main 4:4:4 10 stream from the M5). The result picks ADR-0006's branch: native 4:4:4, 4:2:0 + refinement, or the dual-stream fallback.
2. **Private `CGVirtualDisplay`** on macOS 27: create 939 × 667 pt @2×, capture it with ScreenCaptureKit at 120 Hz. If it's gone or broken, fall back to the public mirroring path (ADR-0007, alternative B) and tell you.
3. **Noise UDP spike:** `IKpsk2_25519_ChaChaPoly_SHA256` handshake + data packets between the two devices; measure per-packet overhead (target < 0.5 ms per frame).
4. **Your real upload:** a `clamshell-bench upload` run from home to a cellular phone (no third-party speed test). This sets the ABR ceiling and tells us which quality tiers are realistic off-LAN.

**Build:**
- `/shared` ClamshellKit skeleton: `Wire` (TLV, versioning, frozen fixtures), `Session` (Noise), `Testing`.
- Mac: virtual display → SCK → VTCompressionSession (low-latency RC, no B-frames, LTR) → seal → UDP.
- Phone: UDP → reassembly → VTDecompressionSession → CAMetalLayer, nearest filtering, 1:1.
- Drop-never-queue, damage skip, refinement frames (120 / 400 ms).
- Bonjour `_clamshell._udp`, a **temporary hard-coded dev pairing** (a key pasted from the Mac log; removed in M3).
- HUD v1 (fps, bitrate, enc/dec ms, drops).
- `/tools/clamshell-bench` harnesses A (barcode patch), C stub, D (text PSNR/SSIM); harness B script for 240 fps footage.

**Tests:** Wire round-trips + fixtures; Noise test vectors (Cacophony) + tamper/replay unit tests; frame-policy unit tests (never queue: a slow decoder drops instead of building latency).

**Demo:** VS Code on the Mac shows on the Duo top half at 939 × 667, scroll at 120 fps, HUD visible; bench report with glass-to-glass p50/p95.

**Exit criteria:** LAN glass-to-glass p50 ≤ 50 ms (harness B); static text refined within 150 ms (harness D); 0 queued frames under a stress scroll; probe results written into ADR-0006/0007.

**Needs you:** run the app from Xcode on the Duo (I'll give exact steps); film one 240 fps clip; run the upload test once.

## M2: Input

**Build:**
- `InputModel` in `/shared`: HID usage → `kVK` table (generated by `/tools/keymap-gen`), full modifier bitmap per packet, 2 s stuck-modifier watchdog, redundant send on the input channel.
- Deck v1 on the phone (laptop posture only): exact ANSI layout, sticky modifiers, F-row swipe, autorepeat on the Mac side.
- Trackpad: relative pointer with `v_out = gain·v_in^γ`, client-side cursor + cursor-shape feed + reconciliation (ADR-0009); tap/click/force-click; 2-finger scroll with real phases and momentum; 3/4-finger gestures mapped per ADR-0013.
- Mac: CGEvent injection, Accessibility permission flow, scroll-phase events.

**Tests:** keymap table completeness (every ANSI key, every modifier combination round-trips); modifier watchdog; gesture recogniser unit tests from recorded touch traces; scroll-phase sequence tests.

**Acceleration fitting:** you use your real MacBook trackpad for a scripted target task, then the Duo. I fit `gain` and `γ` so both take the same time ± 10%. That becomes the "MacBook-like" preset.

**Demo:** code a small change in VS Code and Xcode using only the Duo; ⌘-S, ⌘-Tab (via 4-finger swipe), three-finger Space switch, momentum scroll.

**Exit criteria:** input-to-photon p50 ≤ 60 ms on LAN (harness C); zero stuck modifiers in a 30-min fuzz of random key-down/up sequences with packet loss; pointer at 120 Hz with no visible lag.

**Needs you:** two ~30 min tuning sessions; grant Accessibility on the Mac.

## M3: Internet, pairing, path fallbacks, reconnect

**Build:**
- **`ClamshellEdge.xpc`** (sandboxed): TLS 1.3 with a self-signed certificate, HTTP/1.1 → WebSocket upgrade, generic 404 for anything else, rate limits; shared-memory ring to `ClamshellHost`.
- **P2 home UDP** on port N (random, 20000–59999, chosen at first run) and **P3 WSS** via `URLSessionWebSocketTask` (honours system proxy/PAC).
- **PathRacer** (150 ms stagger), path memory per network, scoring + hysteresis, mid-session migration without re-handshake.
- **Real pairing** (ADR-0014): LAN-only `XXpsk3` with QR `k_pair`, SAS with 3 choices, manual code, admin auth, 8-device cap, Secure Enclave–wrapped key, Touch ID; dev key from M1 removed.
- **IP discovery** (ADR-0005): the source(s) you pick at Checkpoint 2, signed `HomeEndpoint` record, manual-IP fallback, churn log.
- **Network check** screen; revoke / disconnect all / pause; curtain + session notifications.
- `/tools/netsim` profiles `vdsl-up`, `work-443` (UDP blocked + CONNECT proxy + mitmproxy TLS inspection), `cell`, `flap`.

**Tests (integration, the fallback suite):**
- `work-443`: cold connect < 3 s; video works while the outer TLS is intercepted.
- Block UDP with `pfctl` mid-stream → continues on WSS within ≤ 300 ms.
- `flap`: recovery < 2 s after link returns.
- **Security tests from docs/security.md §4:** canary relay test (the Edge and a MITM proxy never see plaintext canary bytes), active tamper test, impersonation test (unpaired key, revoked key, replayed msg1).
- Pairing: wrong SAS, expired window, 3-strike lockout, off-LAN pairing attempt rejected.

**Demo:** at work, open the app → Mac visible in < 3 s through the office proxy; turn Wi-Fi off on the phone → continues on cellular; unplug the router's WAN for 10 s → recovers < 2 s after it returns.

**Exit criteria:** all fallback and security integration tests pass; the definition-of-done items "< 3 s from work", "only TCP 443", "recovers < 2 s" and "VPS/relay can't decrypt" are met and recorded in the CHANGELOG with numbers.

**Needs you (exact steps provided at the start of M3):**
- On the Archer VR400:
  - disable **Remote Management** (or move it off 443);
  - keep **UPnP off**;
  - add a **DHCP reservation** for the Mac;
  - forward **TCP 443** and **UDP N** to it (I'll give N).
- Check whether WE blocks inbound 443: I'll give you a one-command test from cellular. If it's blocked, we pick another TCP port from ADR-0004's fallback list.
- Run the **Network check at work once** and paste me the report.
- One cellular test run.

## M4: Duo UX

**Build:**
- `PostureModel` (hinge + division-region orientation + scene geometry, 150 ms UI debounce, 600 ms display debounce, manual pin) and `ArrangementView`.
- Laptop deck modes **Deck / Split / Pad / Keys**, the Seam bar, legend.
- Flat: direct touch / trackpad toggle, floating mini keyboard, edge swipes for Dock and menu bar.
- Book and Span; cover-screen glance + quick actions + phone session.
- Virtual-display mode switching per posture, "Lock layout", "More space" modes.
- Hardware keyboard via `GCKeyboard` + `wantsPriorityOverSystemBehavior`; ⌥-Tab → ⌘-Tab, ⌃-Space → ⌘-Space remaps; **`GCMouse`** pointer lock and raw deltas.
- Haptics, Shell & Ember theme light/dark, Dynamic Type, VoiceOver labels.

**Tests:** posture state-machine tests from recorded sensor traces (no flapping at the switching angles); mode-change debounce; snapshot tests for each posture in both themes; hardware-keyboard capture tests on device (manual checklist).

**Demo:** fold the Duo through every posture during a live session; the layout follows in ≤ 150 ms and the Mac only changes mode once the hinge is still; close it → glance view → "Lock Mac".

**Exit criteria:** "crisp text at 100% zoom on the top half in laptop posture" (harness D on the real device); every posture usable for 10 minutes of real work; ⌘-Tab behaviour documented with exactly what iOS lets through.

**Needs you:** posture testing on the real Duo, and a Bluetooth keyboard/mouse if you have them.

## M5: Extras

- **Audio:** SCK system audio → Opus (or AAC-ELD) → small jitter buffer; mute toggle.
- **Clipboard:** opt-in, text + images, skips password-manager items (`org.nspasteboard.ConcealedType`), size cap.
- **Files:** drag a file from the Files app onto the Mac view → Downloads, over the same E2E session; progress, cancel.
- **Multi-display:** pick which Mac display to show, or a second virtual display.
- **Wake:** wake the display from the cover screen; keep-awake on AC (`PreventUserIdleSystemSleep`).
- **Auto-start:** `SMAppService` login item; survive restarts.

**Tests:** clipboard type filtering; file-transfer resume and integrity (hash); audio drift/jitter unit tests.

**Demo:** watch a video with sound in Flat posture; copy code on the Mac → paste on the phone; drop a photo onto the Mac.

**Exit criteria:** audio never adds video latency (harness A unchanged with audio on); all features default-off where they cross a privacy line.

## M6: Hardening

- **Fuzzing:** Wire TLV parser, Noise packet handler, WS framing in the Edge (libFuzzer / swift-fuzz harnesses, run in CI nightly).
- **Security review pass** against docs/security.md T1–T16; update accepted risks.
- **P4 HTTPS stream** for proxies that break WebSocket.
- **`/server` relay (P5), optional:** SwiftNIO relay in Docker Compose for a $4–6/month VPS, for the case where home-direct is blocked. It only forwards Noise packets and never holds keys; the canary relay test from M3 runs against it.
- Lossless small-damage overlay experiment (docs/video.md §4.7).
- Crash-free soak test: 8 h session with `flap` every 30 min.
- **App Store readiness:** privacy manifest, export-compliance answer (standard encryption), the screenshots needed, and a review of private APIs (the private `CGVirtualDisplay` is Mac-side only, and the Mac app is Developer ID, so the iOS App Store review doesn't see it).
- **docs/SETUP.md** tested end to end on a freshly erased Mac + a reset phone.

**Exit criteria:** the full definition of done passes in one recorded run; SETUP.md works from zero; no open high-severity items in the threat table.

## Setup notes that come up along the way (go into docs/SETUP.md)

- **Router (Archer VR400):**
  - Remote Management off, or moved off 443;
  - UPnP off;
  - forward only TCP 443 and UDP N to the Mac's reserved IP;
  - firmware updates done by hand.
- **Mac power:**
  - System Settings → Energy: "Prevent automatic sleeping when the display is off" on the power adapter;
  - "Start up automatically after a power failure";
  - charge limit at 80% (macOS battery settings) since the lid stays open on the charger.
- **Mac updates:** manual, so a surprise restart doesn't drop you at work. If FileVault is on, a reboot stops at the pre-boot unlock and remote access is down until you're home (ADR-0016).
- **Permissions:**
  - Screen Recording, Accessibility and Local Network on the Mac;
  - Local Network and Camera (for pairing) on the phone.
  - A Mac menu-bar warning shows before macOS's monthly Screen Recording re-prompt.
- **Build:**
  - Xcode with your Apple Developer team;
  - the iOS app via Xcode or TestFlight;
  - the Mac app signed with Developer ID and notarized (`notarytool` steps in SETUP.md).
