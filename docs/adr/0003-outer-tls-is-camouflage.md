# ADR-0003: Outer TLS is camouflage only; the client accepts any outer certificate

**Status:** Proposed · **Date:** 2026-11-15

## Context
On P3/P4 the phone speaks HTTPS to `homeIP:443`. A work network may inspect TLS: it terminates TLS at a proxy and re-signs with a corporate CA. That CA is probably not trusted by your personal phone, so normal certificate validation would fail. Separately, some inspecting proxies refuse to connect onward to origins with self-signed or IP-only certificates.

Security must not depend on TLS (ADR-0001). The question is only what makes the connection **work** and **look boring**.

## Decision
1. **The client never trusts the outer TLS for security.** The URLSession delegate accepts any server certificate on Clamshell connections. Authentication is the Noise IK handshake inside, with keys pinned at pairing, so a TLS-intercepting proxy sees only ciphertext.
2. **Default outer certificate: self-signed**, generated by the Mac at first launch. **No outside dependency.**
3. **Opt-in: a Let's Encrypt IP-address certificate** (6-day `shortlived` profile), obtained by the Mac with ACME `tls-alpn-01` on port 443. This needs no port 80. Turn it on **only if** the Network check shows the work proxy blocking self-signed origins.
   > ⚠️ **Third-party flag:** Let's Encrypt is an outside service (a public CA). It never sees traffic or keys, only that your IP requested a certificate, and certificate transparency logs make that public. The self-hosted alternative is the default (self-signed). Alternative if LE is unacceptable but self-signed is blocked: P5, a VPS relay with a domain cert, which is itself a CA dependency. There is no fully self-hosted way around a proxy that requires a publicly trusted certificate.
4. **Camouflage:** unauthenticated requests on 443 get a stock-looking `404 Not Found` from a minimal static responder (nginx-like headers, no product name). The WebSocket upgrade succeeds for anyone, but the first binary message must be a valid Noise msg1 from an allow-listed key. Otherwise the socket closes after a randomised 1–3 s delay with no error detail.

## Alternatives considered
- **Pin the outer certificate:** fails under TLS inspection, which is the exact case we must survive.
- **Domain + DNS-01 certificate:** needs a domain and a registrar API, which are outside dependencies. Reconsider if you ever buy a domain (ADR-0005).
- **Obfuscation protocols (obfs4, REALITY-style SNI borrowing):** heavier, a cat-and-mouse game, and closer to "detection evasion" than we need. Plain boring HTTPS is enough for a personal device.

## Consequences
- ➕ It works through TLS inspection with no corporate CA on the phone.
- ➕ No dependency by default.
- ➖ Self-signed may be blocked by some proxies, hence the opt-in LE switch.
- ➖ An inspecting proxy can see that a long-lived WebSocket to a residential IP exists: metadata, not content. docs/security.md lists this under accepted risks.
- **Policy note:** check that your employer allows personal remote-access traffic on its network. Clamshell does not try to hide from a network administrator beyond looking like ordinary HTTPS.
